Personal Projects

Outside of work, I run Ava — a Discord bot I built and maintain for a Pokémon and collectibles restock community that started in Virginia, Maryland, and DC and now covers seven states plus DC. It tracks confirmed restocks, unverified "hope" tips, and line lengths in real time, then turns that history into statistical forecasts members actually use to plan store runs.

It's grown into two connected products. Ava handles the Discord side — moderation, reputation, onboarding, photo privacy, and an AI-assisted server-structure auditor. Its companion web app, Nexus Card Co, is a role-gated dashboard with restock analytics, a searchable card catalog, a portfolio tracker, and a grading ROI calculator. Same Postgres database, two codebases, both on Railway.

AVA · CALLOUTS CORE FEATURE

Real-Time Callout & Tracking System

The heart of the server: four callout types — /restock (confirmed), /hope (unconfirmed tip), /remain (remaining stock check), and /empty — each one pings the right regional role and spins up a dedicated thread with a live, interactive status panel.

  • Crowd-sourced line tracking — members tap a line-length button (0/10/20/30/40/50+) in the thread; a rolling average of the last 10 reports drives a color-coded indicator (🟢/🟡/🔴) that updates live on both the thread panel and the original channel alert at once, with a 5-minute per-user cooldown against spam.
  • One-tap stock status — "Still in Stock" / "Cooked" buttons (with an optional note like "No Pokémon" or "Perfect Order only") rename the thread and update both embeds instantly, so status is visible without opening the thread.
  • Direct Google Maps links — every stored location carries its maps link, so every callout title is clickable straight to directions.
  • Guided location discovery — filing a callout walks region → store type → specific location, populated live from the database for that exact combination; a separate filterable browser lets mods search every stored location by store type and by region/state.
  • Duplicate & conflict protection — a 2-hour cooldown blocks re-reporting the same store/location, and an active unconfirmed hope alert blocks a duplicate restock report until it's confirmed instead.

AVA · FORECASTING CORE FEATURE

Restock Forecasting Engine

Predicts which day of the week a store is most likely to restock, using up to 6 months of community-verified restock history. Four models run side by side:

  • Recency-weighted frequency — a 3-tier decay model (30/90/180-day windows) scores each day of the week independently, so a store restocking every Tuesday and every Sunday can show both near 100%.
  • Bayesian Beta-Binomial — wraps each day's estimate in a Beta posterior with a weak prior, pulling sparse data toward a sane baseline and reporting a 95% credible interval instead of a bare percentage.
  • Empirical Bayes regional pooling — estimates a region-wide base rate for a given day, then uses it as an informed prior so data-poor locations borrow strength from data-rich ones.
  • James–Stein shrinkage — blends each location's own rate with the regional average, weighted by how much history that location actually has.

Those credible intervals used to be the only reason scipy was installed — roughly 70 MB of startup memory on a 512 MB host, for two function calls. The Beta quantile is now about 80 lines of plain Python: a continued-fraction incomplete beta, then Newton steps inside a bracket that falls back to bisection. It was checked against scipy before the dependency came out.

AVA · VISION CORE FEATURE

AI Trading Card Identifier

Members drop a photo of a card into a channel; Claude Vision reads the game, name, number, set, language, and parallel/variant markings (holo patterns, serial numbers, SP/alt-art/treasure-rare stamps for TCGs; rookie/autograph/relic flags for sports cards) from a single structured-extraction prompt.

The result is cross-referenced against five different sources — pokemontcg.io, Scryfall, YGOProDeck, a One Piece card API, and eBay — to return live pricing, and a follow-up view lets the member log the card straight into their collection by condition.

AVA · ALERTS ACTIVE

Deal & Restock Alert Pipeline

Listens to a channel fed by a third-party price-diff bot, parses product name and price straight out of its embeds (handling plain dollar amounts, USD-in-parens conversions, and bare "USD" suffixes), and matches against mod-configured watch rules — keyword, price ceiling, and optional location filter.

A match pings the right role in the right channel, with per-rule cooldown deduplication so a flaky source feed can't spam the same deal twice.

Members can also set their own. Keyword alerts saved on the Nexus dashboard — with exclusion words, a store list, and a price ceiling — are matched in a single Postgres query each time a third-party restock monitor posts. Everyone who matched gets one combined ping, by DM if they asked for it, falling back to a channel mention when their DMs are closed.

AVA · AUDIT ACTIVE

AI-Assisted Server Structure Audit

A Claude-backed way to answer "is this server actually consistent?" One-shot mode builds a digest of channel/role structure and activity counts, sends it in a single request, and posts back what's actually wrong — prioritized, regional asymmetry first. A conversational mode lets a mod @mention the bot and ask questions; Claude picks its own tools to go look things up, read-only, no changes made.

  • Privacy by construction — never reads message content, only channel/role metadata and the bot's own tables; the one tool that touches history reads timestamps only.
  • Regional parity is the reason it exists — every region is supposed to be structurally identical, and drift there breaks features silently rather than loudly.
  • Degrades gracefully — the conversational agent uses a beta SDK surface, so it's wrapped in an import guard; the one-shot audit keeps working even if that path doesn't.

AVA · PRIVACY ACTIVE

Fail-Closed Face Blurring

Discord can't edit an attachment in place, so watermarking a restock photo means deleting the member's post and reposting it as the bot — which makes the bot the publisher. Before anything goes back up, each photo runs through a face detector (YuNet, via OpenCV's DNN module) and any face it finds is blurred.

  • Fails closed — a missing model, an unreadable image, an inference error, or a detection that wants to blur more than half the frame all mean "couldn't guarantee it," and the member's original post is left alone. The whole check runs before anything is deleted.
  • Tuned on a real failure — loosening the detection threshold to catch more faces turned a photo of a cat into a smear across 62% of the frame, so it went back to the default and the coverage guard went in.
  • Memory-aware — a detector is built per photo (about 3 ms) instead of shared, because a shared one was measured holding around 170 MB for the life of the process. Inference runs on a worker thread, off the event loop.
  • Hard to crop out — the watermark is a tiled diagonal text mark rather than a corner logo, and re-encoding drops EXIF and GPS data from what gets reposted.
  • Known limit — it catches clear, front-facing faces and misses people who are far away or turned to the side. It's a safety net, and members are told so.

AVA · MARKETPLACE ACTIVE

Marketplace Rules & Enforcement

The buy/sell forums have their own moderation layer, split across both codebases: mods write removal rules in a web editor on Nexus, and the bot checks every new For Sale post against them.

  • A small rule grammar — a rule is a list of groups, and a post matches if any group has all of its required terms and none of its excluded ones. Dashes count as spaces, * allows up to three words between two terms, and title and body are joined with a separator so a phrase can't straddle the two.
  • Broken rules can't widen — a rule the bot can't parse is skipped and logged, never read as "match everything." The editor rejects exactly the cases the bot would skip, so the mod finds out on save instead of never.
  • One table, one owner — the bot owns the schema and the dashboard only writes rows, so two apps never migrate the same table in different directions.
  • Strikes — one is a warning, two is seven days read-only, three removes marketplace access. The block is a per-member permission overwrite, because Discord ranks a member's own overwrite above any role's; it's reapplied if they leave and rejoin.
  • Listing flags — anonymous to the seller but visible to mods, on purpose: the realistic abuse is sellers flagging competitors, and mods can only spot that if they can see who's flagging.

AVA · EXPANSION ACTIVE

Multi-State Expansion

The server began as three neighbors — Virginia, Maryland, and DC — with region names written directly into the code. In October it added Pennsylvania, Texas, Florida, Illinois, and Colorado, which meant turning "region" into data first.

  • One-command provisioning — an admin command previews, then clones a template state's roles, channel permissions, and onboarding option. Anything that already exists is reused, so a run that stopped halfway can simply be run again.
  • Validated at startup — the region tables are checked on boot for missing IDs, duplicate labels, a state in no zone, or a bad time zone, so a typo shows up in the deploy log instead of on the first callout.
  • Stores keyed by ID, not name — there's an Arlington Target in Virginia and another in Texas. Joins moved to a location ID so their histories can't merge, and on the dashboard a member with a Texas role sees Texas data only, filtered in SQL.
  • Per-area time zones — Texas runs on Central. Reporting cutoffs, store hours, and the forecast math use the area's own clock, not the server's.

NEXUS · CATALOG ACTIVE

Card Catalog, Tally & Trade Calculator

A searchable price catalog for Pokémon and Riftbound singles and sealed product. Guests can use it without logging in, limited to the newest sets.

  • Live search — trigram (pg_trgm) GIN indexes are built at startup, in-flight requests are aborted so a slow response can't overwrite a newer one, and rows and filter facets come back together.
  • Quick Tally — a running list of cards with CSV export. Cells are escaped against spreadsheet formula injection, since card names come from third-party price APIs and aren't mine to trust.
  • Trade calculator — two sides valued at market, with editable prices. It lives entirely in the browser's local storage; nothing about a trade is sent to the server.
  • A second game without a rewrite — adding Riftbound replaced a hard-coded game list on every page with one registry of games and feature flags that each picker and endpoint reads.

NEXUS · GRADING ACTIVE

Grading ROI Calculator

Answers one honest question per grade: if this card sells at the going rate for that grade, what do you actually keep after grading fees, shipping both ways, insurance, and marketplace cuts — compared with just selling it raw today. Deliberately skips the tempting-but-fake math: no probability of pulling a 10, no expected-value blending. A confident number built on a guessed input is worse than no number.

NEXUS · PORTFOLIO ACTIVE

Card Portfolio & Price Tracker

Lets members track what they actually own — lot by lot, not averaged, since buying the same card twice at different prices needs two rows to compute a real return. Every lot points at one shared, deduplicated price catalog, so a card tracked by three different members' portfolios still costs one price-API credit a day, not three. All money is stored and computed as Decimal, never float.
